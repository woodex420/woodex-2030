## 2 · Findings — bugs found & FIXED during this QA (server)

| ID | Sev | Symptom (pre-fix) | Root cause | Fix |

| **QA-01** | **P0** | `POST /api/orders` → **500 “ref is not defined”** — public checkout broken; order row inserted but response failed (partial write) | ref string inlined into `.run(...)`; later task-title & `emit()` referenced a bare `ref` that was never bound | bound `const ref = "WX-" + …` before insert, reused everywhere |
| **QA-02** | **P1** | `POST /api/quotes/:id/invoice` → **500 “no such column: client_id”** — quote→invoice conversion broken | clients table PK is `id`; query selected `client_id c` from `clients` | `SELECT id AS c FROM clients …` |
| **QA-03** | **P2** | `POST /api/pages/:id/rollback` without `version_id` → **500 bind error** | `undefined` passed straight to a SQLite param | numeric guard → `400 version_id required`; UI already sends it (verified) |
| QA-04 | P3 | `GET /api/leads?status=&q=` silently ignored filters | route never implemented server-side filters | added case-insensitive `status` + `q` (name/company/interest/contact/ref) filters |
| QA-05 | P3 | `/api/health` counts too thin to trust ops dashboards | only 4 tables reported | added `users` + `invoices` counts |
| QA-06 | — | “Login doesn’t reach dashboard” (user-reported) | iframe-partitioned `localStorage` → token lost → first fetch 401 → bounce to Login | in-memory token truth + best-effort persistence (shipped `5364f18`) |
