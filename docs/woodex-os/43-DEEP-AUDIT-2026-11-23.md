## Part C — the shop, and its integration

### What is live

`https://woodex-2030.vercel.app`, built from `main` at `92c16dd`. Its four settings on Vercel are the site's
address, the database's address, and the first owner's e-mail and password. Read today:

| `woodexfurniture.pk/robots.txt`: "Disallow: /" | The business's real site tells every search engine to stay out |

### What works

`npm run typecheck:all` passes. `npm run vercel:build` passes and renders its 16 static pages. CI's gate for the
shop is green on `main`: the API's batteries on SQLite and on PostgreSQL, and its browser journeys (the scripts
are the catalogue from the import to the checkout, the enquiry into the CRM, the quotation template, the page
builder, and every dashboard screen). Today, on the built shop: 34 addresses opened at a desk and on a phone, all answered and none
with a broken picture; 25 detail pages of series, projects, services and articles, all with their heading; 19
category links, each with products behind it; a product put into the cart and sent as an order request
(reference WX-4301, "No payment was collected"); an enquiry sent from Contact and found in the old dashboard's
API. The quotation form refuses to go without its "Project type", in the browser's own words.

### The integration, link by link

The plan: the shop stays a React application, reads the catalogue from Laravel and sends enquiries, quote
requests and orders to Laravel (master plan §1).

| Link | Built? | On the live shop? |
|---|---|---|
| An enquiry form → the admin's CRM (`POST /api/v1/leads`) | Yes: the address, its contract, the shop's caller, a contract check in CI | **Off.** `VITE_LEAD_API_MODE` is not set: the form writes to the old system |
| A basket → a quote request in the admin (`POST /api/v1/quote-requests`) | Yes. In this mode the shop refuses a basket in which a colour or material was chosen, and sends the visitor to the team instead | **Off** |
| Category pages (headings, texts, questions) ← the admin | Yes: `GET /api/v1/catalogue/categories`, through a bridge of the shop's API | **Off.** No address of an admin is set |
| Pictures ← the admin's media library | Yes: `GET /api/v1/media`, through a bridge | **Off** |
| **Products ← the admin** | **No.** `/api/v1` has seven addresses and none for products. The 170 real products cannot leave the admin | — |
| An order → the admin | **No.** The admin has no orders (wave 6) | — |

So today the shop and the admin are two systems side by side. What joins them is built for four links, proved in
tests and on the rehearsal, and switched off; the link that matters most for a shop, its products, is the next
round of the plan (T-105). Switching any link on for the live shop needs an admin that keeps data, and the demo
keeps none: that is T-006 again.
